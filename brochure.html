The Diagnosis

What went wrong with Agile

Twenty-five years ago, a manifesto valued people over processes and working software over documentation. Then an industry turned those values into processes and documentation.

⚠

Ceremony replaced collaboration

Sprint planning, refinement, retrospectives, daily standups. The meetings meant to enable agility became the process that prevents it.

⚠

Tickets replaced understanding

Requirements go into documents. Documents become epics. Epics become stories. Stories get estimated. By the time work starts, the original intent is three translations away.

⚠

Charts replaced honesty

Velocity tracking and burndowns exist to answer "whose fault is it?" — not to help anyone ship better software. This is accountability theater.

⚠

A translation class emerged

Professional project managers sit between stakeholders and developers, translating in both directions. Both sides would be better off talking directly.

The Shift

Not better tooling. Different structure.

Jarista does not optimize the current paradigm. It replaces it.

Flat ticket board

Cards in columns. No structural relationships. Context lives in people's heads.

PM tool as separate system

State drifts from code within days. Someone must manually reconcile.

Velocity and burndowns

Prediction theater. "We estimated 40 points" is not an engineering insight.

Cross-team dependencies via Slack

Tribal knowledge. Someone remembers. Or doesn't.

Status reported by humans

Someone writes a summary. It is already stale when sent.

Living graph

Multi-level specs and tasks with typed edges. Structure is explicit and queryable.

Graph as sibling to source

Versions, branches, merges with your code. Reviewed in PRs. Cannot drift.

Structural progress

Specs are fulfilled or they aren't. The graph is the status. No interpretation needed.

Proxy nodes

A dependency is a node in your graph pointing to theirs. Visible. Trackable. No meetings.

Status computed by AI

The graph is semantically rich. AI reads it and answers questions. No one writes a report.

Core Architecture

Three ideas. Everything else follows.

01

Codified multi-level graph

Specifications and tasks are Java records — compiled, type-checked, connected by typed edges. The graph captures what defines what, what fulfills what, and what depends on what. Coverage gaps are structural, not guesswork.

02

PM and code as siblings

The graph lives in .jarista/ next to src/. It branches when you branch. It merges when you merge. It is reviewed in your pull requests. The plan cannot drift from the code because it is subject to the same version control.

03

Proxy nodes for cross-team collaboration

To depend on another team's work, create a proxy node that references a node in their graph. No shared server. No shared database. No shared process. Just a typed reference that caches remote state and syncs on demand.

// This is your project plan. It compiles.

new SpecNode("oauth-flow", "OAuth 2.0 login flow",
    edges(
        definedBy("epic-user-auth"),
        fulfilledBy("task-impl-token-refresh"),
        dependsOn(proxy("team-b", "spec-oauth-provider"))
    )
);

// Dangling reference? Compile error.
// Spec with no fulfilling task? Graph query.
// Status of team-b's OAuth provider? Cached in the proxy.
